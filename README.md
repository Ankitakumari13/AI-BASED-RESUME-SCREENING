# AI-Based Resume Screening and Candidate Shortlisting System

A machine learning project that screens resumes against a job description, scores how well each candidate matches, and returns a ranked shortlist with the reasons behind every score. It includes a full ML notebook, a synthetic dataset generator, and a Streamlit web app for recruiters.

**Live demo:** https://ankita-resume-screener.streamlit.app/

> **Note:** The model is trained on a **synthetic** dataset, so the scores are a proof of concept, not a measure of real-world hiring accuracy. A human should always make the final hiring decision.

---

## Features

- **Resume anonymisation:** removes names, emails, phone numbers and links before scoring, to reduce bias risk.
- **Match-based features:** TF-IDF text, resume-to-job cosine similarity, skill overlap (with synonym handling such as ML = machine learning), years of experience, and role fit.
- **Model comparison:** Logistic Regression, Linear SVM, Naive Bayes, Random Forest and Gradient Boosting, evaluated with accuracy, precision, recall, F1 and ROC-AUC.
- **Ranked shortlisting:** candidates are ordered by predicted probability of selection, with matched and missing skills shown for each one.
- **Explainability:** top terms that push a decision towards select or reject.
- **Web app:** paste a job description, upload resumes (PDF, DOCX or TXT), and download the ranked shortlist as CSV.

## Results

Evaluated on a held-out test set (20% of the data):

| Model | Accuracy | ROC-AUC |
|---|---|---|
| Logistic Regression (text + match features) | ~0.86 | ~0.94 |
| Gradient Boosting (match features) | ~0.86 | ~0.94 |
| Linear SVM (text + match features) | ~0.86 | ~0.94 |
| Logistic Regression (TF-IDF text only) | ~0.69 | ~0.76 |

- 5-fold cross-validation ROC-AUC for the best model: about 0.936 (± 0.005).
- Ranking quality: Precision@10 per role is about 0.97, against a 0.45 random baseline.
- Key finding: resume-to-job **match features** raise accuracy from about 0.69 to 0.86, so screening works best as a matching problem, not plain text classification.

## Dataset

`resume_screening_dataset.csv` is generated by `generate_dataset.py` (seeded, so it is reproducible).

- 10,000 candidate-job pairs, 1,500 job descriptions, 15 roles.
- About 45% select and 55% reject.
- The decision comes from a hidden weighted score (required skills, preferred skills, experience, education, projects, certifications, role fit) plus random noise.
- `Reason_for_decision` is generated after the label and **leaks it** (a model using only that column scores near 100%), so it is excluded from modelling.

To change the difficulty, edit `NOISE_SD` and `SELECT_RATE` at the top of `generate_dataset.py` and run it again.

## How it works

1. **Clean:** strip personal identifiers and markdown, lowercase the text.
2. **Featurise:** TF-IDF vectors for resume and job description, cosine similarity, skill overlap, years of experience, resume length and role fit.
3. **Score:** a Logistic Regression model outputs the probability that a candidate is selected.
4. **Rank:** candidates are sorted by that probability and the top N are shortlisted.

## Limitations

- The data is synthetic, so real resumes may behave differently.
- Scanned (image-only) PDFs have no text layer and are skipped.
- The skill list covers the 15 roles in the dataset, so other roles are matched mainly through text similarity.
- Do not upload real candidates' resumes to the public demo.
